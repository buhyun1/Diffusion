# t_discrete_coverage 
자유도(ν) 변경 실험, 커버리지 관점의 재검증

|  |  |
|---|---|
| 날짜 | 2026-09-03 |
| 데이터 | FashionMNIST class 0 (T-shirt/top), 확산모형 학습 1000장 |
| 질문 | ν를 낮추면 생성 분포가 원본 분포를 더 빠짐없이 덮는가 |
| 결론 | **가설과 반대.** corr=0.99에서 coverage는 ν와 함께 증가하고, corr=1에서는 ν=30이 정점이다 |

## 1. 질문

`t_discrete_tail`은 무거운 꼬리가 생성 분포의 **꼬리**를 두껍게 하는지를 물었다. 이번에는 다른 질문이다.

> ν를 낮추면 생성 분포가 원본 분포를 **더 빠짐없이 덮는가**?

덮는 정도를 재려면 FID로는 부족하다. FID는 충실도와 다양성을 한 숫자에 섞는다. 그래서 낮은 ν가 이겨도 더 잘 덮어서인지, 샘플이 더 그럴듯해서인지 구분되지 않는다.


## 2. 구현

스케줄은 `t_discrete_tail`과 같은 선형 보간 **µ_t = 1−t, σ_t = t** 다. 경계조건(µ_0=1, σ_0=0, µ_T=0, σ_T=1)을 만족하는 가장 단순한 선택이다.

| 파일 | 역할 |
|---|---|
| `posterior.py` | 논문 Eq. 2 · 7 — perturbation kernel, prior, reverse posterior (`t_discrete_tail`과 동일) |
| `unet.py` | D_θ (`t_discrete_tail`과 동일) |
| `autoenc.py` | 특징공간용 오토인코더 — 128-d 병목, 학습 · 불러오기 · 특징 추출 |
| `train_autoenc.py` | 오토인코더 단독 학습 (class 0 전체 6000장, 500장 held-out) → `results/autoenc.pt` |
| `t_discrete_coverage.ipynb` | 스케줄 · ν별 학습 · 샘플링 · coverage/density/FID 계산 · 그림 (ν × corr 스윕) |

### 실행

```bash
python train_autoenc.py
```

이어서 `t_discrete_coverage.ipynb`를 위에서부터 실행한다.
- 오토인코더 학습: `results/autoenc.pt`가 없으면 노트북이 직접 학습한다.
- ν별 체크포인트: `results/nu<값>/ckpt.pt`가 있으면 불러오고, 없으면 학습한다.

- 경로는 실행 위치 기준 상대경로다. FashionMNIST를 미리 `data/FashionMNIST/raw`에 두어야 한다.
- 설정: ν ∈ {3, 5, 10, 30, 100, 300, 500, 1000}, corr ∈ {0.99, 1}, 100 epoch, 1000스텝, 생성 1000장, k=5.
- 학습 시 t는 `sigmoid(N(−1.74, 1.2²))`에서 뽑는다 (logitnormal).
- 7절의 corr 0 / 0.05 / 0.5 결과를 다시 내려면 노트북의 `CORRS`에 해당 값을 추가한다.

## 3. 특징공간 — 분류기에서 오토인코더로

**1차: 10-클래스 분류기 (폐기)**

분류기는 티셔츠냐 가방이냐만 가르면 손실이 줄어든다. 그래서 **티셔츠들 사이의 차이를 버려도 대가가 없다.** 그런데 coverage가 재려는 것이 정확히 그 클래스 내부 변이다.

**2차: 오토인코더**

class 0만 재구성하도록 학습했다. 티셔츠를 복원하려면 소매 길이, 프린트, 실루엣을 병목에 담을 수밖에 없다. 복원 결과에서 프린트 로고, 줄무늬, 민소매 실루엣이 모두 살아남는 것을 확인했다.

## 4. 지표

모두 같은 128-d 특징공간에서 잰다. 같은 거리 행렬 `d = cdist(f_real, f_gen)` (1000×1000)을 다르게 요약한 것이다.

| 지표 | 방향 | 묻는 것 | 기준선 |
|---|---|---|---|
| `coverage` | 실제 → 생성 | 원본을 빠짐없이 덮었나 | 0.972 |
| `density` | 생성 → 실제 | 생성물이 원본과 같은 자리인가 | 0.994 |
| `real_nn` | 실제 → 생성 | 안 덮인 원본이 얼마나 머나 | 14.71 |
| `gen_nn` | 생성 → 실제 | 베낀 게 아니라 새로 만들었나 | 14.09 |
| `FID` | 전역 통계 | 구름의 중심·모양이 맞나 | 8.67 |

## 7. corr이 ν보다 훨씬 중요하다

coverage 값 (ν = 3 / 100):

| corr | ν=3 | ν=100 |
|---|---|---|
| 0 | 0.080 | 0.066 |
| 0.05 | 0.086 | 0.074 |
| 0.5 | 0.147 | 0.160 |
| 0.99 | 0.812 | 0.881 |
| 1 | 0.670 | 0.717 |

corr을 0에서 0.99로 바꾸면 coverage가 **10배** 움직인다. ν는 같은 corr 안에서 최대 0.07을 움직일 뿐이다.

corr이 낮은 구간(0, 0.05)에서는 ν=3이 근소하게 앞선다. 하지만 그 구간은 FID가 530~580이고, 생성 격자가 **모든 ν에서 똑같은 민무늬 흰 티셔츠**다. 전형적인 모드 붕괴라 우열을 논할 수 없다.

## 8. 정리

- FID는 ν=3일 때 제일 좋고, 커버리지는 corr=0.99일 때 제일 좋다.
- ν=3일 때 커버리지가 더 좋을 것으로 예상했는데, 실험 결과는 그렇지 않았다.
- corr=0.99로 줬을 때 분산이 살아 있어 다양성이 더 많이 나타날 것이라 생각했는데, 그렇게 나타나지 않았다.
